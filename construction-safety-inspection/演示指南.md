图片检测页保留三张推荐图片，按下面顺序演示：

1. `demo_images/featured_safety_exception.jpg`：双人对照场景，检测框清晰，适合先展示完整流程。
2. `demo_images/test_site_gate_01.jpg`：进场安全帽检查，适合展示多人场景和未佩戴风险。
3. `demo_images/test_survey_team_03.jpg`：测量作业团队，适合展示多人佩戴安全帽的合规场景。

## 置信度阈值怎么讲

页面上的阈值明确指**人员框置信度阈值**。模型底层会分别输出安全帽框和人员框，安全帽框使用内部召回阈值 `0.15` 保留下来，只用于和人员框做空间关联；页面阈值用于筛选人员框，低于该值的人员不计入人数，也不会写入违规台账。也就是说，演示时调节的是“这个人员目标是否可信”，不是单独调节安全帽框。

YOLO/Ultralytics 在模型推理阶段会先生成候选框，再按置信度和 IoU 做非极大值抑制（NMS）去掉重复框；项目没有另写一套 NMS，而是调用 YOLO 的标准推理流程。NMS 解决“同一个目标出现多个重叠框”，页面阈值解决“保不保留这个人员结果”，两者是不同层次的规则。图片页另外使用 960 输入尺寸和增强推理，优先改善远处小目标的召回；视频页使用 640 输入尺寸，优先保证速度。

| 阈值 | 适用场景 | 演示说法 |
|---|---|---|
| 0.25 | 小目标、远距离、希望多找一些人 | “召回优先，可能多一些误检。” |
| 0.35 | 明天默认推荐 | “在召回和误检之间取平衡。” |
| 0.55 | 目标清晰、希望结果更保守 | “严格模式，只保留更确定的检测。” |

建议先用 0.35 演示。如果画面里人员很小，调到 0.25；如果出现明显误检，再调到 0.55。图片页在初次结果没有识别到佩戴者时会自动用更大尺寸复核一次，仍然不需要重新训练。阈值只能筛选模型已经找到的目标，完全没有检测框时，继续降低阈值也不一定能找回目标。

## 图片检测流程怎么讲

1. **上传**：Gradio 接收图片并统一转换为 OpenCV 的 BGR 格式。
2. **预处理与推理**：图片检测页使用较大的输入尺寸和增强推理，让远处的小目标更容易被模型看到。YOLO 模型输出候选框、类别和置信度。
3. **目标关联**：模型的原始类别是“安全帽”和“人”，系统把安全帽框与人员框按位置关联，得到“佩戴安全帽/未佩戴安全帽”。
4. **阈值筛选**：低于页面阈值的人员框不计入结果，也不会写入台账。
5. **判定与展示**：系统统计佩戴人数、未佩戴人数并绘制框；如果存在达到阈值的未佩戴目标，就生成违规记录写入 SQLite 台账。

多人图片中出现漏框，通常是人员太小、被遮挡、姿态重叠或背景干扰造成的检测召回不足。阈值只能筛选已经找到的候选框，不能凭空找回完全没有输出的目标；这也是现场系统需要保留人工复核的原因。

## 推荐演示顺序

1. 图片页选择 `featured_safety_exception.jpg`，阈值 0.35，说明输入、检测框、佩戴人数和未佩戴人数。
2. 选择 `test_site_gate_01.jpg`，阈值调到 0.25，说明多人场景下提高召回率的做法。
3. 打开违规台账，说明图片检测发现违规后会自动记录时间、来源、人数和严重度。
4. 打开视频页，载入脚手架视频，分析帧率设为 2，展示结果视频和抽帧标注画廊。
5. 最后打开智能报告页。该页需要网络和 `.env` 中的模型 API，生成时间通常为 30–60 秒。

视频页会对连续抽帧中的未佩戴目标做轻量轨迹关联。同一个人只计为 1 名未佩戴人员，连续出现的多帧仍会保留“违规帧数”指标，但不会把同一个人重复累加到人数和台账中。

## 双 Agent 怎么讲

双 Agent 指两个不同职责的语言模型流程，不是两个视觉检测模型：第一个“安全分析 Agent”读取 SQLite 台账，汇总频次、人数和严重度；第二个“报告撰写 Agent”接收结构化分析、台账数据和法规知识库，生成正式巡检报告。视觉检测由 YOLO 完成，双 Agent 只负责检测结果之后的风险分析和文字报告。
