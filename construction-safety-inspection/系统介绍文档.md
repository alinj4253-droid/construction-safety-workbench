## 一、30 秒了解这个系统

**一句话**：把工地的摄像头变成一个不知疲倦的"电子安全员"——它自动盯着画面里的每一个人，
发现谁没戴安全帽就记一笔账，最后还能自动写一份正式的《安全巡检报告》交给你。

**它做了三件事**：

```
① 看得见 —— AI 视觉检测：从图片/视频里找出"戴安全帽的人"和"没戴安全帽的人"
② 记得住 —— 违规台账：每次发现违规，自动记入本地数据库（时间/地点/人数/严重程度）
③ 写得出 —— 双 Agent 报告：两个大模型分工合作，把台账数据变成一份引用真实法规的巡检报告
```

**形象比喻**：传统模式下，安全员拿着记录本在工地转一圈，看到没戴帽子的记一笔，
回来手写报告。本系统 = 给他配了一双**永远不眨眼的眼睛**（YOLO 检测）、
一个**自动记账的本子**（SQLite 台账）、和一个**帮他写报告的秘书**（双 Agent）。

---

## 二、它解决什么问题（项目背景）

建筑工地上，"进入施工现场必须佩戴安全帽"是铁律（依据：《安全生产法》第四十五条、
《建筑施工安全检查标准》JGJ 59-2011）。但现实中：

| 痛点 | 本系统的应对 |
|---|---|
| 人工巡检走不全：工地大、出入口多，安全员看不过来 | 摄像头 7×24 小时盯着，AI 逐帧分析 |
| 违规记录靠手写：事后难统计、难追溯、难考核 | 自动写入数据库，一键导出 CSV，随时统计 |
| 巡检报告手写费时：每次都要组织语言、翻法规条文 | 双 Agent 自动生成，数据引用台账、法规引用内置知识库 |
| 违规没有分级：单人忘戴和群体性不戴一样处理 | 自动分级：单人未戴=一般，≥2人同时未戴=严重 |

## 四、四大功能详解（怎么用 + 背后在干什么）

### 页签 1：📷 图片检测 —— 最直观的入口

**你能做什么**：
1. 上传一张工地照片（或直接点页面上的**施工现场样例**按钮，用内置图片演示）
2. 拖动"人员置信度阈值"滑块（默认 0.35）
3. 点【开始检测】

**你会看到什么**：右边出现画好框的图片——
- 绿色框 = 系统判断为佩戴安全帽的人员
- 红色框 = 系统判断为**未佩戴安全帽的人员**（违规！）
- 下方文字告诉你要不要记违规

**背后发生了什么**：
AI 模型（YOLO，一种目标检测算法）先扫描整张图，分别输出**安全帽候选框**和**人员候选框**，每个框都有一个 0~1 的置信度。
系统再检查安全帽框是否位于人员框的头部区域：匹配到安全帽就判定为佩戴，人员框没有匹配到安全帽就判定为未佩戴。
页面滑块作用于**人员框**：低于页面阈值的人员不计入统计，也不会写入违规台账；安全帽框使用较低的内部召回阈值，只用于佩戴关联。

YOLO/Ultralytics 在模型推理阶段会先生成候选框，再通过置信度筛选和 IoU 非极大值抑制（NMS）去掉同一目标的重复框。NMS 是 YOLO 推理库提供的通用规则，项目调用它的标准流程；页面滑块则是项目在后处理阶段针对人员结果设置的业务阈值，两者不是同一个规则。

### 页签 2：🎬 视频检测 —— 更接近真实巡检

**你能做什么**：上传一段工地视频（手机横拍即可），设置抽帧频率（默认每秒 2 帧），点开始。

**背后发生了什么**：视频就是连续的图片。系统按设定频率抽取画面逐帧检测
（不必每帧都查——相邻画面几乎一样，抽帧能省算力）。
系统会对连续抽帧中的未戴帽人员做轻量轨迹关联，同一个人只计一次，最后输出一份画好框的标注视频和汇总台账记录。

### 页签 3：📋 违规台账 —— 工程价值所在

**你能做什么**：
- 【刷新台账】：查看历史违规记录表格（时间/来源/未戴人数/严重度）
- 【清空台账】：演示前重置用的

**背后发生了什么**：每次违规都写进了本地数据库文件（`data\ledger.db`，SQLite），
**关机重启也不会丢**。"严重"的判定规则：同一画面里 ≥2 人同时未戴 = 严重（群体性违章，
管理问题的信号），单人未戴 = 一般（个体行为）。这张表就是工地安全管理的数据资产。

### 页签 4：🤖 智能报告 —— AI 的点睛之笔

**你能做什么**：直接点【🚀 生成巡检报告】，等 30~60 秒。

**你会看到什么**：一份完整的《施工现场安全帽佩戴巡检报告》（Markdown 格式），
含巡检概况、主要问题、**法规依据**（引用真实条文）、风险研判、整改建议、复查安排。

**背后发生了什么（双 Agent 分工）**：
```
台账数据 + 法规知识库
        │
        ▼
┌─────────────────────┐      ┌─────────────────────┐
│ 安全分析 Agent       │      │ 报告撰写 Agent       │
│（快模型 gpt-4o-mini）│ ──→ │（主力模型 gpt-4.1-mini）│
│ 负责"想"：           │      │ 负责"写"：           │
│ · 风险等级判定       │      │ · 正式公文文风       │
│ · 违规规律分析       │      │ · 六章结构排版       │
│ · 匹配法规条款       │      │ · 数据→结论的完整呈现 │
│ 输出：结构化 JSON    │      │ 输出：巡检报告       │
└─────────────────────┘      └─────────────────────┘
```
为什么用两个模型？**分析要快要便宜，撰写要好要正式**——各司其职，
这是"多智能体协作"思想最朴素的落地。法规知识库（`kb\regulations.json`）
里的条文都经过北大法宝核实，Agent 只能引用库里的条款，**不许自己编法条**。

> 注意：此页签需要联网调用大模型 API；断网时前三个页签照常可用。

## 五、把系统串起来：一次完整巡检的生命周期

```
工地摄像头/手机拍的视频
   │
   ▼ 视频检测页签：抽帧 → YOLO 逐帧检测 → 发现未戴帽的帧
   │
   ▼ 违规判定：置信度过滤 → 单人=一般 / 多人=严重
   │
   ▼ 写入台账：时间、来源、人数、严重度（SQLite 持久化）
   │
   ▼ 一段时间后…… 点【生成巡检报告】
   │
   ▼ 安全分析 Agent 读台账 → 风险研判（等级/规律/法规匹配）
   │
   ▼ 报告撰写 Agent → 《巡检报告》落盘 exports\，可交付安全总监
```

## 七、常见问题（FAQ）

**Q1：双击 run.bat 后黑窗口一闪就没了？**
→ 多半是 `.venv` 被移动/删除了。看窗口里的报错提示；确认项目在
`D:\Desktop\ProfPractice\construction-safety-inspection` 没被改名。

**Q2：界面打开了，但"智能报告"页签报错？**
→ 该功能需要联网。检查网络；还不行看 `.env` 里 API 配置是否有效。

**Q3：检测把戴帽的人漏了/没戴的没查出来？**
→ 先调低"置信度阈值"滑块（如 0.25）试试。AI 对**远距离小目标**和**非工地场景**
（如街景摩托车流）表现会下降——本模型是用工地/安全帽数据训练的，
**用 demo_images 里的工地图片演示效果最佳**。

**Q4：想重新训练模型？**
→ 见 `README.md` 第 4 节（prepare_dataset.py → train.py，GPU 约 6~7 分钟）。

**Q5：台账数据在哪？能删吗？**
→ `data\ledger.db` 单文件数据库，删掉=清空历史；或用界面上的"清空台账"按钮。

**Q6：换台电脑能用吗？**
→ 需要同样有 NVIDIA 显卡 + 重新装环境（README.md 有依赖清单）。
最稳的演示方式还是用本机。
