Chunk 切分规则

保留条款上下文，同时控制送入检索和生成阶段的文本规模。

1

清洗文本

解析网页和 PDF，去除脚本、样式和多余空白，保留法规正文与来源元数据。

2

句子边界切分

优先按句号、问号、感叹号、分号等边界切分，避免从条款中间截断。

3

650 字目标长度

单个片段目标上限约 650 字；遇到无标点超长段落时按目标长度硬切。

4

100 字重叠窗口

相邻片段保留约 100 字重叠，让跨段的责任主体、条件和整改要求保持连续。

5

来源元数据

每个 Chunk 保留法规名称、发布部门、文号、生效状态、原文链接和片段编号。

6

可追溯引用

回答会返回命中的资料名称和片段编号，便于答辩时回到原文核对。

检索与生成技术

当前页面只展示关键技术点，详细运行过程见下方流程。

Dense 检索

使用本地 256 维哈希词/二元词向量，适合捕捉问题和条款之间的词语组合相似性。

BM25 稀疏检索

根据关键词在资料中的词频、逆文档频率和文档长度进行匹配，适合法规名称、文号和条款关键词。

Weighted RRF

融合 Dense、BM25、实体图谱和关系图谱结果，当前权重为 0.5、0.3、0.2、0.2。

Agentic RAG

复用原 RAG 的查询分析、检索路由、Evidence Judge、有限重试和流式生成链路。

LLM 生成

支持 OpenAI 兼容 API 流式生成；接口不可用时，使用命中的检索证据进行本地兜底。

会话记忆

使用 SQLite 保存会话和消息，通过近期对话窗口与滚动摘要支持多轮追问。
