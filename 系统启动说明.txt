施工安全管理工作台——系统启动说明

一、当前电脑快速启动

项目位置：D:\Desktop\ProfPractice

1. 打开上述文件夹，双击 start.bat。
2. 保持启动窗口打开，等待出现 Uvicorn running on http://127.0.0.1:8010。
3. 浏览器访问：http://127.0.0.1:8010
4. 选择登录身份，输入密码。

如果浏览器已经能正常打开系统，就直接使用，不必重复启动。
当前电脑已准备过虚拟环境和依赖；通常无需重复执行安装步骤。

二、通过 PowerShell 启动（推荐用于排查问题）

打开 PowerShell，逐行执行：

Set-Location -LiteralPath 'D:\Desktop\ProfPractice'
.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8010

看到启动成功提示后，打开：http://127.0.0.1:8010
停止系统：在启动窗口中按 Ctrl+C，等待服务退出。
以后再次使用时，重新执行启动命令或双击 start.bat 即可。

三、新电脑或核心 ZIP 解压后的首次安装

1. 安装 Python 3.11。
2. 解压核心 ZIP，在包含 README.md、backend、frontend、requirements.txt
   和 start.bat 的那一层文件夹打开 PowerShell。
   注意：新电脑的解压目录可能不同，不必使用本说明中的 D 盘路径。
3. 逐行执行下面的命令：

py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

4. 依赖安装成功后，执行：

.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8010

5. 浏览器访问：http://127.0.0.1:8010

首次安装依赖需要联网，视觉检测相关依赖较大，请等待安装完成。
若提示找不到 py，可用已安装的 Python 3.11 的完整路径替代 py -3.11。
以后无需重复安装依赖，直接按第一节或第二节启动。

四、大模型 API 配置与离线使用

当前原项目目录中的 .env 已单独配置，正常使用时不要覆盖它。
核心 ZIP 不含真实密钥；新电脑需要自行配置，步骤如下：

1. 如果项目根目录还没有 .env，复制 .env.example，并把副本命名为 .env。
   文件名必须是 .env，不是 .env.txt。
2. 用记事本打开 .env，在 OPENAI_API_KEY= 后填写自己的 CloseAI API 密钥。
3. 其他地址和模型名称可先沿用模板；模型必须是自己账号实际可用的型号。
4. 保存后重启系统。

没有密钥也可以启动。系统会使用有标识的离线原文检索、模板起草和规则复核。
如需主动演练离线，可在 .env 中把 LLM_ENABLED=1 改成 LLM_ENABLED=0，
保存并重启。恢复在线时再改回 1。
请勿将含真实密钥的 .env 发给他人或提交到 Git。

七、常见问题

1. 双击 start.bat 后窗口立即关闭：
   按第二节在 PowerShell 中启动，查看错误信息；优先检查虚拟环境和依赖是否安装。

2. 提示端口 8010 被占用（WinError 10048）：
   先访问 http://127.0.0.1:8010，确认是否已有本系统在运行。
   同一个数据库请只运行一个系统实例，不要反复双击启动。
   如果端口由其他程序占用，且本系统没有运行，可把命令末尾的 8010 改为 8012，
   然后访问 http://127.0.0.1:8012。

3. 页面打不开：
   确认启动窗口仍在运行，地址使用 http 而不是 https，端口与启动命令一致。
   不要直接双击 frontend\index.html，应通过本地服务地址访问。

4. 提示缺少某个 Python 模块：
   在项目根目录执行：
   .venv\Scripts\python.exe -m pip install -r requirements.txt

5. AI 显示“当前为离线兜底结果”：
   系统仍可使用。若需要在线模型，请检查 .env、账号额度、网络和模型可用性。

6. 监控视频或检测不可用：
   检查 videos 中的视频、上述 best.pt 权重及视觉依赖是否完整。
   检测只产生待核实线索，必须人工确认后才能进入隐患台账。

7. 登录状态过期：
   重新选择账号并登录即可。

更多架构与功能边界，请查看项目中的 README.md。


八、AI 监控本轮更新（2026-10-18）

当前正在演示的 8010 主服务没有重启。监控及首页统计由 8014 独立监控服务
读取同一个现有数据库提供，隐患办理、RAG、台账接口继续使用主服务。
刷新浏览器后，进入 AI 监控 → 视察大屏，即可看到最新真实检测帧。
点击“依次检测四路录像”可串行重跑四组视频；也可切换单路并检测当前录像。
“录像回放”保留原视频，“YOLO 检测帧”显示离线抽样结果，不是实时监控。

需要启动独立监控服务时，在项目根目录执行：
PowerShell -ExecutionPolicy Bypass -File .\scripts\start_monitor_service.ps1

此脚本仅适用于主页面端口 8010；默认独立监控端口为 8014。
已有同版本服务会直接复用，不会重启主服务、初始化数据库或恢复其他业务任务。
日志：backend\data\monitor-service.out.log、monitor-service.err.log。
连接配置：frontend\monitor-runtime.local.json，属于本机运行配置，不提交 Git。
若提示监控服务版本过旧，先等待检测任务结束，仅停止该独立服务进程再执行脚本。
不要为更新监控而结束正在运行的隐患办理服务。

如果以后从最新代码重新启动完整主服务，且希望直接使用主服务的监控接口，
可将上述本机连接配置的 api_origin 设为空字符串，再刷新页面。
主服务运行旧版本代码时，请保留 8014 独立监控连接。

默认检测在每个完整片段均匀抽取 8 帧，人员作业面阈值为 0.50，远景/俯拍最低
为 0.65。可逐帧查看类别、置信度、录像时间和检测框。零检出不能证明没有隐患。
人工确认仍是线索进入隐患台账的前提；本轮已保留原数据库、历史和视频素材。
